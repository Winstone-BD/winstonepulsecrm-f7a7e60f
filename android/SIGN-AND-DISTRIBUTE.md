# Winstone Pulse Android app — Android Studio এ খুলে নিজের কী দিয়ে সাইন করা

এই ফোল্ডারটি একটি সম্পূর্ণ Android Studio প্রজেক্ট। ভেতরে কোনো গোপন কী নেই — আপনি নিজের keystore দিয়ে সাইন করবেন।

## ১) খুলুন
Android Studio → **Open** → এই ফোল্ডার বাছুন → Gradle sync শেষ হওয়া পর্যন্ত অপেক্ষা করুন।

## ২) নিজের কী তৈরি করুন (একবারই)
Android Studio → **Build → Generate Signed App Bundle / APK → APK → Create new…**
- Key store path: যেমন `~/keys/winstone-release.jks`
- Password, key alias, key password ঠিক করে লিখে রাখুন — হারালে আর একই অ্যাপ আপডেট দেওয়া যাবে না।

## ৩) কী-এর তথ্য প্রজেক্টে দিন
`local.properties.example` কপি করে `local.properties` নাম দিন, তারপর নিজের মান বসান:

```
sdk.dir=/path/to/Android/sdk
RELEASE_STORE_FILE=/absolute/path/winstone-release.jks
RELEASE_STORE_PASSWORD=আপনার পাসওয়ার্ড
RELEASE_KEY_ALIAS=আপনার alias
RELEASE_KEY_PASSWORD=আপনার key পাসওয়ার্ড
CRM_BASE_URL=https://crm.winstonebd.com
```

`local.properties` কখনো কাউকে পাঠাবেন না।

## ৪) APK তৈরি করুন

**অফিসিয়াল রিলিজের জন্য (GitHub ছাড়া, এক কমান্ডে):** `local.properties`-এ অনুমোদিত সার্টিফিকেট
ফিঙ্গারপ্রিন্ট `RELEASE_CERT_SHA256=` বসান, তারপর প্রজেক্ট ফোল্ডার থেকে চালান:

```
bash scripts/build-signed-apk.sh                                  # macOS / Linux
powershell -ExecutionPolicy Bypass -File scripts\build-signed-apk.ps1   # Windows
```

স্ক্রিপ্টটি টেস্ট চালায়, সাইন করা APK বানায়, সাইনার ফিঙ্গারপ্রিন্ট/প্যাকেজ/ভার্সন মিলিয়ে দেখে, এবং
`android/release-out/`-এ APK + `.sha256` + রিলিজ রেকর্ড রাখে। কিছু না মিললে বিল্ড বন্ধ করে দেয়
(পাসওয়ার্ড কখনো দেখায় না)। কী ফাইল (`.jks`) অবশ্যই প্রজেক্ট ফোল্ডারের বাইরে রাখবেন।
বিস্তারিত: `docs/ANDROID_OFFICIAL_RELEASE_HANDOVER.md`।

হাতে চালাতে চাইলে:
টার্মিনালে:

```
./gradlew clean assembleRelease
```

ফাইল পাবেন: `app/build/outputs/apk/release/app-release.apk`

## ৫) অফিসে বিতরণ
APK ফাইলটি এজেন্টদের দিন (ইমেইল, ড্রাইভ লিংক বা সরাসরি ফোনে কপি)। ফোনে ইনস্টলের সময়:
- "Unknown sources / এই সোর্স থেকে ইনস্টল" অনুমতি দিতে হবে
- অ্যাপ চালুর পর **ফোন, কল লগ, মাইক্রোফোন, স্টোরেজ** — সব অনুমতি দিতে হবে, নাহলে কল রেকর্ডিং জমা হবে না

## গুরুত্বপূর্ণ
- একই keystore দিয়েই ভবিষ্যতের সব আপডেট সাইন করতে হবে।
- অ্যাপে এজেন্ট প্রথমবার ফোন নম্বর + পাসওয়ার্ড দিয়ে লগইন করলে ডিভাইসটি CRM-এ নিবন্ধিত হয়; IT Console থেকে যেকোনো সময় বাতিল করা যায়।

## ৬) নতুন ভার্সন সব কম্পানি ফোনে পৌঁছানো (v1.8 থেকে)
1. `versionCode` / `versionName` বাড়িয়ে `./gradlew clean assembleRelease` চালান।
2. IT Console → **ফোন অ্যাপের নতুন ভার্সন** → একই version code/name দিয়ে APK আপলোড করুন।
3. প্রকাশের পর প্রতিটি ফোনের অ্যাপ খোলার সময় নিজেই "নতুন ভার্সন এসেছে" ব্যানার দেখাবে;
   এজেন্ট **ডাউনলোড ও ইনস্টল** চাপলে ফোন নিজের ইনস্টল অনুমতি চাইবে।
4. "বাধ্যতামূলক" টিক দিলে ব্যানার এড়ানো যাবে না।
5. একই প্যানেলে দেখা যায় কোন ফোন কোন ভার্সনে আছে — যেসব ফোনে এখনো পুরনো ভার্সন,
   সেগুলো "আপডেট বাকি" হিসেবে দেখাবে। কোনো ফোনে দূর থেকে জোর করে ইনস্টল করা যায় না।

## রেকর্ডার (v2.16) — APK বানানোর আগে ও পরে
- `versionCode 27 / versionName 2.16` — এই সংস্করণে ফোনের নিজস্ব কল রেকর্ডারের ফাইল তুলে CRM-এ পাঠানো যুক্ত হয়েছে।
- `versionCode 33 / versionName 2.22` — সর্বশেষ কোড থেকে প্রথম কোম্পানি-সাইন বিল্ড: মাইক্রোফোন অনুমতি ও রেকর্ডিং সম্মতি IT Console-এ পাঠায়; কল হিস্টোরি (READ_CALL_LOG) থেকে আসল কথা বলার সময়। সাইনার অবশ্যই `2E:61:50:E6…4E:1C:7E:6D` (অপেক্ষমাণ — কী-রক্ষক মিলিয়ে নিশ্চিত করবেন)।
- APK: `./gradlew testDebugUnitTest` তারপর `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`।
- ফোনে: ফোনের Dialer-এ **অটো কল রেকর্ডিং চালু** করুন, আর অ্যাপ "অডিও ফাইল পড়ার" অনুমতি চাইলে **Allow** দিন।
- পরীক্ষা: একটি কল করুন → ২ মিনিটের মধ্যে CRM-এর **Recorder** পাতায় কলটি লেখা ও সারাংশসহ দেখা উচিত।
- iPhone: Apple ফোন কল রেকর্ড করতে দেয় না; iPhone-এ CRM-এর Recorder পাতা ব্রাউজারে খুলে ভয়েস নোট রাখুন।

## ৭) অফিশিয়াল 2.22 বিল্ড — কী-রক্ষকের ধাপ (GitHub ছাড়া)
প্রজেক্টে ভার্সন আগেই `2.22 (code 33)` করা আছে। কী-রক্ষক নিজের কম্পিউটারে:

1. Lovable থেকে **সর্বশেষ কোড** ডাউনলোড করে আনজিপ করুন (পুরনো ফোল্ডার ব্যবহার করবেন না)।
2. কোম্পানির কী (`.jks`) প্রজেক্ট ফোল্ডারের **বাইরে** রাখুন। এটি সেই একই কী হতে হবে যেটি v2.3 সাইন করেছিল —
   **নতুন/আলাদা কী দিলে স্ক্রিপ্ট বিল্ড বন্ধ করে দেবে**, আর ফোনে আগের অ্যাপের ওপর আপডেটও বসবে না।
3. `android/local.properties`-এ কী-এর পথ, পাসওয়ার্ড, alias আর এই লাইনটি দিন:
   ```
   RELEASE_CERT_SHA256=2E:61:50:E6:06:52:45:C1:B2:B5:41:37:51:2D:63:ED:40:0D:22:9B:88:1D:1B:91:5A:29:06:17:4E:1C:7E:6D
   ```
4. প্রজেক্ট ফোল্ডার থেকে চালান: `bash scripts/build-signed-apk.sh` (Windows: `powershell -ExecutionPolicy Bypass -File scripts\build-signed-apk.ps1`)।
5. শেষে "Official release APK verified" লেখা আসতে হবে। `android/release-out/`-এ তিনটি ফাইল পাবেন:
   `winstone-connect-2.22-33-release.apk`, `.sha256`, `.release-record.txt`।
6. এই **তিনটি ফাইল** (শুধু এগুলো — `.jks` বা `local.properties` কখনো নয়) Lovable চ্যাটে আপলোড করুন।

এরপর Lovable ফাইলটি আবার যাচাই করবে (সাইনার, প্যাকেজ, ভার্সন, SHA-256), গোপন স্টোরেজে রাখবে, আর
IT Console → Releases-এ "অফিশিয়াল রিলিজ" হিসেবে দেখাবে। CRM শুধু তখনই অফিশিয়াল দেখায় যখন অনুমোদিত কী +
`com.winstone.connect` + 2.22 বা তার পরের স্ক্রিপ্ট-বিল্ড মেলে। সব এজেন্টকে দেওয়ার আগে একটি ফোনে
Real phone test checklist পাস করান।

### 2.22-এ নতুন যা আছে (ফোনে পরীক্ষা করার তালিকা)
- উপরের বারে, হোম স্ক্রিন আইকনে আর অ্যাপ খোলার স্ক্রিনে সোনালি Winstone Pulse লোগো।
- লোগোর নিচে CRM সংযোগের লাইন: সবুজ/হলুদ/লাল, শেষ সফল সিঙ্কের সময় (ঢাকা সময়), আর "আবার চেষ্টা" বোতাম।
- প্রতিটি কল আর রিপোর্টে "ফোন লগ যাচাই" লাইন। শুধু রিং বাজলে কখনো "কথা হয়েছে" দেখায় না।
- ইন্টারনেট ফিরে এলে আটকে থাকা কল রিপোর্ট কয়েক সেকেন্ডের মধ্যে আপনাআপনি আবার পাঠানো হয় (একই রিপোর্ট আইডি, তাই ডুপ্লিকেট হয় না)।
- কল তালিকার নাম এখন "সাম্প্রতিক কল লগ"।
- পরীক্ষা: এয়ারপ্লেন মোড চালু → একটি কল রিপোর্ট শেষ করুন → এয়ারপ্লেন মোড বন্ধ → কয়েক সেকেন্ডে রিপোর্ট CRM-এ দেখা যাবে, আর উপরের লাইন সবুজ হবে।

## ৮) Git (GitHub) থেকে অফিশিয়াল বিল্ড — মালিকের সিদ্ধান্ত ২ নভেম্বর ২০২৬
কী-রক্ষকের কম্পিউটারের বদলে GitHub-এ বিল্ড করা যায়। স্ক্রিপ্ট আর যাচাই একই থাকে।

**একবার সেটআপ (কী-রক্ষক + রিপোজিটরির অ্যাডমিন):**
1. Lovable → Project settings → Git → নতুন **প্রাইভেট** রিপোজিটরি সংযুক্ত করুন। রিপোজিটরিতে 2FA বাধ্যতামূলক রাখুন।
2. রিপোজিটরি → Settings → Environments → **`android-release`** নামে environment বানান →
   **Required reviewers**-এ ১–২ জন অনুমোদনকারী দিন (প্রতিটি বিল্ডে তাঁদের অনুমতি লাগবে)।
3. ওই environment-এর **Secrets**-এ চারটি জিনিস রাখুন (চ্যাটে বা কোডে কখনো নয়):
   - `ANDROID_KEYSTORE_BASE64` — `.jks` ফাইলের base64: Mac/Linux-এ `base64 -i winstone-release.jks | tr -d '\n'`, Windows-এ `[Convert]::ToBase64String([IO.File]::ReadAllBytes("winstone-release.jks"))`
   - `WINSTONE_KEYSTORE_PASSWORD`
   - `WINSTONE_KEY_ALIAS`
   - `WINSTONE_KEY_PASSWORD` (key ও store পাসওয়ার্ড একই হলে এটিও একই)
4. অনুমোদিত আইডি কোড `2E:61…7E:6D` workflow-এ লেখা আছে। অন্য কী দিলে বিল্ড বন্ধ হবে।

**প্রতিটি রিলিজ:** Actions → **Android official release** → Run workflow → অনুমোদনকারী Approve করবেন →
শেষে **Artifacts** থেকে `winstone-connect-2.22-official-release` ZIP নামান (APK, `.sha256`, `.release-record.txt`) →
তিনটি ফাইল Lovable চ্যাটে আপলোড করুন। ফাইলগুলো ৭ দিন পরে GitHub থেকে নিজে মুছে যায়। বিল্ড শুরুর আগেই চারটি গোপন তথ্য আছে কি না আর প্রজেক্টের ভার্সন 2.22 (33) কি না যাচাই হয়; কিছু না মিললে বিল্ড থেমে যায়।

প্রতিটি অ্যাপ পরিবর্তনে **Android tests** নিজে চলে (কোনো কী বা পাসওয়ার্ড লাগে না)।
